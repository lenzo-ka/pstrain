## 1. Method (reproducible)

### Upstream inventory

1. **Config template.** `~/dev/cmu/sphinxtrain/etc/sphinx_train.cfg` read in full (332 lines);
   every `$CFG_*` with its inline comment captured. Cross-checked against the only other shipped
   template, `templates/librispeech/etc/sphinx_train.cfg`, via `diff` — the two differ only in
   corpus-specific values (`.ptm.` vs `.cont.`, 5000 senones, NPART), so the `etc/` copy is the
   default surface.
2. **Per-stage command lines.** The tuned values live in the Perl drivers, not the C defaults.
   Extracted with:
   `grep -rn -E "^\s*(my \$|'?-)(mwfloor|minvar|varfloor|abeam|bbeam|topn|stwt|ssplit|csplit|...)" --include="*.pl" scripts/`
   plus a Python regex sweep over `RunTool\('<tool>'...\)` blocks in `scripts/*/*.pl`.
   Every stage script that BW/tree/prune touches was then read in full:
   `20.ci_hmm/{baum_welch,norm,norm_and_launchbw,slave_convg,split_gaussians}.pl`,
   `30.cd_hmm_untied/baum_welch.pl`, `50.cd_hmm_tied/{baum_welch,norm_and_launchbw}.pl`,
   `40.buildtrees/{buildtree,make_questions}.pl`, `45.prunetree/{prunetree,tiestate}.pl`,
   `05.vector_quantize/{agg_seg,kmeans,slave.VQ}.pl`, `000.comp_feat/make_feats.pl`,
   `prepare/maketopology.pl`, `decode/psdecode.pl`, `lib/SphinxTrain/Util.pm`.
3. **C program defaults.** Python regex over `{ "-opt", ARG_TYPE, "default", ... }` in
   `src/programs/{norm,agg_seg,bldtree,prunetree,init_gau,init_mixw,mk_mdef_gen,kmeans_init,inc_comp,mk_flat,tiestate,make_quests}/parse_cmd_ln.c`
   and `src/programs/bw/train_cmd_ln.c`. These matter only where the Perl driver does **not**
   override them — noted per row below.
4. **Front end actually used in training.** `000.comp_feat/make_feats.pl:112-131` shows exactly
   which `sphinx_fe` flags SphinxTrain sets; everything else falls through to
   `include/sphinxbase/fe.h:80-258` defaults, which were read for the fall-through values.

### pstrain inventory

1. `git show main:pstrain/lib/pipeline/context.py` — `FeatParams` / `TrainParams` / `SplitParams`
   and `DEFAULT_CONFIGS`; `etc/configs.yaml` (shipped profiles) read directly.
2. `git show main:pstrain/lib/pipeline/tasks.py` — the *actual* pipeline; every `run_bw_training`
   / `build_tree` / `prune_tree` / `make_quests` call site inspected for which parameters are
   passed and which are left at the callee default. This is the authoritative surface: the
   step/model/pydantic tables (§4) are not consulted by it.
3. `git show main:pstrain/lib/steps/{train,split,cd_pipeline,ci_hmm}.py`,
   `git show main:pstrain/lib/{bw,dtree,mdef,flat,agg_seg}.py`,
   `git show main:pstrain/lib/pipeline/feat_params.py`.
4. Synthetic command lines / hardcoded floors in
   `git show main:csrc/libs/libpstrain/pstrain_{bw,dtree,fe,agg_seg,mdef_gen,inc_comp,param_cnt}.c`,
   located by grepping for `{ "-...", ARG_` tables and for bare numeric literals passed into
   `mod_inv_read_*` / `feat_init` / `gauden_*`.
5. Decode side: `git show main:pstrain/lib/testing/decoder.py`.

Verdicts: **MATCH** / **DEVIATION-BUG** / **DEVIATION-DELIBERATE** / **UNEXPOSED** (value is
hardcoded, user cannot change it — orthogonal to whether it matches) / **PSTRAIN-ONLY** /
**UPSTREAM-ONLY**.

## 3. Ranked findings

Ranked by plausible contribution to the 5.84 pt WER gap on the parity benchmark.

### F0 — `-topn` pinned to 1 in Baum-Welch (highest)
- **Delta.** `pstrain_bw.c:173` passes literal `1` for `n_top`; upstream passes the full density
  count for CI (`20.ci_hmm/baum_welch.pl:130`) and CD-tied (`50.cd_hmm_tied/baum_welch.pl:126`),
  and only CD-untied uses 1 (`30.cd_hmm_untied/baum_welch.pl:109`). The value reaches
  `gauden_set_n_top` (`libmodinv/mod_inv.c:265`) so it is live, not advisory.
- **Impact hypothesis.** From `cd-2g` onward, every frame's posterior goes entirely to the single
  best-scoring Gaussian. Mixture weights drift toward one-hot, the non-winning components in each
  senone stop receiving mean/variance counts, and each `inc_comp` split adds components that the
  next BW pass immediately starves. That would make the 1g→8g mixture growth cosmetic — a
  plausible several-point WER effect on its own, and it is exactly the kind of defect that a
  1-Gaussian smoke test cannot see. Also note the comment at `pstrain_bw.c:171` (*"use topn=1
  since we typically have 1 density for flat models"*) — the assumption was true when written and
  stopped being true when splitting was added.
- **Suggested fix lane.** Plumb `n_top` through `pstrain_bw_config_t`; default it to the model's
  `n_density` read from the means file; expose as `TrainParams.topn`. Verify by comparing
  `mixture_weights` entropy at `cd-8g` before/after.

### F1 — BW forward beam `-abeam` 1e-50 instead of 1e-90
- **Delta.** `bw.py:32` sets `a_beam = 1e-50`; all seven upstream bw stages use `1e-90`
  (`20.ci_hmm/baum_welch.pl:175` and siblings). `pstrain_bw.c:99` would have used 1e-90 as its own
  fallback, but `tasks.py:301,349` → `steps/train.py:108` always constructs a `BWConfig()`, so the
  Python value wins. The inline comment — *"widened for stability"* — is backwards: 1e-50 is
  **forty orders of magnitude tighter** than 1e-90.
- **Impact hypothesis.** Alpha pruning that aggressive drops low-probability paths early in each
  utterance, biasing counts toward whatever the current (initially flat) model already likes.
  Effect is worst on long utterances and on the first iterations, exactly where a flat model needs
  the wide beam. Compounds with F0.
- **Suggested fix lane.** Set `a_beam = 1e-90`, fix the comment, and expose `abeam`/`bbeam` on
  `TrainParams`. Cheap; run the parity benchmark against it in isolation.

### F2 — decision-tree state weights uniform instead of `1.0 0.05 0.0`
- **Delta.** `cd_pipeline.py:368-378` calls `build_tree` without `state_weights`; `dtree.py:80`
  therefore passes NULL and `pstrain_dtree.c:419-422` substitutes `1/n_state` each. Upstream uses
  `1.0 0.05 0.0` for 3-state HMMs (`40.buildtrees/buildtree.pl:114-115`) — and the comment block at
  `buildtree.pl:100-105` explicitly records three rejected alternatives, i.e. this vector is a
  tuned artifact, not an arbitrary choice.
- **Impact hypothesis.** When building the tree for state *k*, upstream scores a candidate split
  almost entirely on state *k*'s own distribution (weight 1.0) with a 5 % nod to state *k+1* and
  nothing from *k+2*. pstrain averages all three states equally, so all three per-phone trees see
  nearly the same objective and split on nearly the same questions. The 200-senone inventory ends
  up clustering by phone rather than by phone-and-position — a direct, large hit to CD model
  quality.
- **Suggested fix lane.** Port the `$CFG_STATESPERHMM`-indexed table from `buildtree.pl:110-123`
  into `cd_pipeline.build_tree_one`, pass it explicitly, and make `pstrain_dtree.c`'s uniform
  fallback log a warning rather than being the silent default.

### F3 — decode-side language weight, word penalty and beams left at PocketSphinx defaults
- **Delta.** `decoder.py:138-143` sets only `hmm`, `dict`, `beam`, `wbeam` (+ optional `fdict`,
  `lm`, `pl_window`). Upstream sets nine decode parameters (`psdecode.pl:119-132`): `lw`,
  `fwdflatlw`, `bestpathlw` all = 10 (`sphinx_train.cfg:320`); `wip` = 0.2 (`:323`); `beam`,
  `fwdflatbeam`, `pbeam`, `lpbeam`, `lponlybeam` all = 1e-80 (`:321`); `wbeam`, `fwdflatwbeam` =
  1e-40 (`:322`). pstrain's CD beams are 1e-48 / 7e-29 (`decoder.py:74-75`).
- **Impact hypothesis.** Language weight 6.5 vs 10 and word-insertion penalty 0.65 vs 0.2 shift the
  acoustic/LM balance substantially — on a small-vocabulary benchmark this is routinely worth 1–3
  WER points by itself, in either direction. Because it is a *measurement*-side deviation it can
  mask or exaggerate any acoustic-model fix, so it should be resolved **before** the other lanes'
  results are trusted.
- **Suggested fix lane.** Add an upstream-parity decode profile (`lw=10`, `wip=0.2`, all beams
  1e-80/1e-40) and re-run the benchmark with the *current* models. This isolates how much of the
  5.84 pt is decoder configuration rather than training.

### F4 — `bldtree` split parameters took the C defaults, not the tuned Perl values
- **Delta.** `dtree.py:29-37` mirrors `bldtree/parse_cmd_ln.c` rather than
  `40.buildtrees/buildtree.pl:148,154-159`. Specifically: `ssplitmax` 5 vs **7**, `ssplitthr`
  8e-4 vs **0**, `csplitmax` 100 vs **2000**, `csplitthr` 8e-4 vs **0**, `mwfloor` 1e-4 vs **1e-8**.
  Note `buildtree.pl:106-107` shows `8e-4` / `1e-5` as *commented-out alternatives* — upstream
  deliberately moved to zero thresholds.
- **Impact hypothesis.** Nonzero split thresholds stop growing the tree once likelihood gain falls
  below 8e-4, and `csplitmax 100` caps composite-question size 20× below upstream. Both shrink the
  pool of candidate splits *before* `prunetree` picks the best 200 — so pruning chooses from a
  worse menu. `mwfloor` 1e-4 vs 1e-8 additionally flattens the CD-untied mixture weights the tree
  clusters on, which for 1-density untied models is the whole signal.
- **Suggested fix lane.** Change the `dtree.build_tree` defaults to the Perl values (or better:
  pass them explicitly from `cd_pipeline`, leaving the C-mirroring defaults as the raw-API
  contract), and surface them on `TrainParams`.

### F5 — `make_quests` question set half the upstream size, no refinement iteration
- **Delta.** `dtree.py:155-158`: `npermute=6`, `quests_per_state=8`, `niter=0`. Upstream:
  `npermute => 12`, `qstperstt => 20`, `niter => 1` (`40.buildtrees/make_questions.pl:78-80`).
- **Impact hypothesis.** The question set is the alphabet the trees can split on. 8 questions per
  state instead of 20, built from half the permutations and never refined, gives every tree a
  coarser vocabulary — compounds F2 and F4 in the same direction (under-discriminative senones).
- **Suggested fix lane.** Same lane as F4; pass `npermute=12, quests_per_state=20, niter=1` from
  `cd_pipeline.run_make_questions`.

### F6 — convergence criterion has different units *and* a different threshold; unexposed
- **Delta.** Upstream: absolute per-frame log-likelihood improvement, threshold **0.1**, with the
  cfg comment explaining why it must be absolute (`sphinx_train.cfg:247-250`;
  `20.ci_hmm/norm_and_launchbw.pl:155,170,185`). pstrain: *relative* change
  `abs(cur-prev)/abs(prev)` with threshold **0.001** (`steps/train.py:211-213`), and
  `tasks.py:301-311` never passes it, so it cannot be changed from a config.
- **Impact hypothesis.** At a typical 39-dim per-frame log-likelihood around −70 to −80, 0.001
  relative ≈ 0.07–0.08 absolute — coincidentally close to upstream's 0.1, so the *stopping point*
  is probably in the right neighbourhood today. The hazard is that it is data-scale-dependent: any
  change to feature scaling silently changes the iteration count. Lower priority than F0–F5, but
  it makes iteration counts non-comparable between runs.
- **F6b (bundled).** The `abs()` at `steps/train.py:211` means a *decreasing* likelihood reads as
  converged and exits silently. Upstream logs `*WARNING*: NEGATIVE CONVERGENCE RATIO`
  (`norm_and_launchbw.pl:166-167`) — a diagnostic the current BW-update investigation would want.
- **Suggested fix lane.** Switch to the absolute-delta form with default 0.1, restore the negative
  warning, and expose `convergence_ratio` + `min_iterations` on `TrainParams`.

### F7 — transition-probability floor 1e-5 instead of 1e-4
- **Delta.** `pstrain_bw.c:166` passes 1e-5 to `mod_inv_read_tmat`; upstream's live value is the
  `bw` C default 1e-4 (`bw/train_cmd_ln.c:345-348`), since no Perl driver overrides `-tpfloor`.
- **Impact hypothesis.** Small. A looser floor lets near-zero skip/exit transitions persist. With
  `SKIPSTATE=no` the topology has few candidate near-zero entries, so this is second-order.
- **Suggested fix lane.** Fold into the F0/F1 BW-parameter lane; set 1e-4 and expose it.

### F8 — CD-tied mixture-weight floor 1e-8 instead of 1e-5
- **Delta.** `pstrain_bw.c:159` uses 1e-8 for every stage. Upstream uses 1e-8 for CI
  (`20.ci_hmm/baum_welch.pl:98`) and CD-untied (`30…:88`) but **1e-5** for CD-tied
  (`50.cd_hmm_tied/baum_welch.pl:87`).
- **Impact hypothesis.** Small-to-moderate, and interacts with F0: the CD-tied stage is where
  senones are data-starved, and upstream's heavier floor there is exactly the smoothing that keeps
  rare components alive. With `topn=1` (F0) the two together make component death much more likely.
- **Suggested fix lane.** Same BW-parameter lane; make the floor stage-dependent.

### F9 — `pass2var` hardcoded off in the text-transcript BW entry point
- **Delta.** `pstrain_bw.c:377` passes literal `0` for `pass2var` in
  `pstrain_bw_process_utt_text`, while `pstrain_bw_process_utt_mfcc` (`:498`) and
  `pstrain_bw_process_utt` (`:585`) pass `ctx->pass2var`. The live pipeline uses the MFCC path
  (`steps/train.py:161`), so this is currently latent.
- **Impact hypothesis.** None today; a trap for anyone who switches entry points. Note also that
  `pstrain_bw_normalize` branches on `ctx->pass2var` (`pstrain_bw.c:631`), so the text path would
  accumulate one-pass counts and normalise them two-pass — silently wrong variances.
- **Suggested fix lane.** One-line fix in the same BW lane; add a test that runs one iteration
  through each entry point and compares variances.

### F10 — stage 21 (`multipron_align`) has no pstrain equivalent
- **Delta.** This fork defaults `$CFG_MULTIPRON = 'yes'` (`sphinx_train.cfg:227`), which runs
  `sphinx3_align` after CI and feeds a realigned, variant-tagged transcript into CD training
  (`sphinx_train.cfg:199-221` documents the precedence). `tasks.py:763-832` registers no align
  task, so pstrain's CD stages train on the raw reference transcript.
- **Impact hypothesis.** Moderate and confounded with the multipron work already in flight — CD
  models trained on unaligned reference text vs upstream's aligned variant labels. Flagged here for
  completeness; the multipron lane owns it.

### F11 — tree-build failures degrade silently
- **Delta.** `cd_pipeline.py:379-381` catches a `RuntimeError` from `build_tree` and writes
  `"# Trivial tree for {phone} state {state}"`. Upstream aborts the stage.
- **Impact hypothesis.** Not a parameter deviation, but it can silently remove phones from the
  senone inventory, which would look exactly like a tuning problem. Worth a count-and-report at
  minimum so a benchmark run cannot quietly ship a degraded tree set.

### F12 — three parameter tables are declared but never read (honesty gap, not a value delta)
`pstrain/lib/steps/ci_hmm.py:28-37`, `pstrain/lib/model.py:173-186,237-250` and
`pstrain/lib/config/models.py:160-214` all declare `abeam: 1e-90`, `topn`, `varfloor`,
`mixw_floor`, `tmat_floor`, `min_iterations`, `convergence_threshold`. **None of them reach the
engine**: `ci_hmm.py:108-125` discards its own `params` and delegates to `build_pipeline(...).run`,
and `tasks.py` reads only `ctx.train.{n_state,n_senones,max_iterations,multipron_training}` and
`ctx.feat.*`. Anyone auditing pstrain by reading those tables would conclude `abeam=1e-90` and
`topn` is configurable — both false (F0, F1). Recommend deleting or wiring them; a table that lies
about the running configuration is worse than no table.

## 4. Coverage statement

**Reached and compared in full:**
`sphinx_train.cfg` (all `$CFG_*` / `$DEC_CFG_*`); the `.cont.` training path end to end
(comp_feat → flat init → CI BW → CD-untied → make_quests → bldtree → prunetree → tiestate →
CD-tied BW → Gaussian splitting → package → decode); `bw`, `norm`, `bldtree`, `prunetree`,

**Not reached — audit is silent on these:**

1. **`bw` internals.** Only the *parameters* into `baum_welch_update` were compared, not the
   forward/backward implementations. pstrain vendors `csrc/programs/bw/{forward,backward,
   baum_welch,next_utt_states}.c`; whether they are byte-identical to upstream was **not** checked.
   The `next_utt_states_graph` multipron builder is pstrain-specific and unaudited here.
2. **`pstrain_align.c`, `pstrain_map_adapt.c`, `pstrain_kdtree.c`, `pstrain_kmeans.c`,
   `pstrain_flat.c`, `pstrain_delint.c`, `pstrain_param_cnt.c`** — no `{ "-opt", ARG_ }` tables
   found by the sweep, and none are on the default pipeline. Their internal literals were not
   inspected. `pstrain_flat.c` in particular deserves a look (mk_flat's `-nstream 4` /
   `-ndensity 256` C defaults are dangerous if ever inherited).
3. **The semi-continuous / PTM path** (`.semi.`, `.ptm.`, `s2_4x`, 4-stream, `05.vector_quantize`,
   `90.deleted_interpolation`, `mk_s2sendump`). pstrain is continuous-only; upstream parameters
   for those stages were catalogued as UPSTREAM-ONLY but not compared.
4. **LDA/MLLT (`01`/`02`), VTLN (`12`), forced alignment (`10`/`11`), MMIE (`60`–`65`), MLLR
   adaptation (`80`), G2P (`0000`)** — all default-off upstream; their parameter tables were read
   only far enough to confirm the defaults are off.
5. **The decoder's own front end.** pstrain decodes from audio (`tasks.py:698-707`) rather than
   from `.mfc`, so decode-time feature extraction runs through PocketSphinx's FE configured by the
   packaged `feat.params`. Whether that reproduces `pstrain_fe.c` bit-for-bit was not verified.
6. **`pstrain/lib/native_worker.py` and the in-flight worker/transport lane.** Confirmed to
   contain no BW parameter defaults today; if that lane introduces its own config path it must be
   re-audited.
7. **LM construction.** `tasks.py:671-676` builds a 3-gram with `smoothing="auto"`; upstream
   supplies the LM externally (`$DEC_CFG_LANGUAGEMODEL`). Not comparable, not compared.
8. **`etc/feat.params` template substitution.** Upstream's template (`etc/feat.params:1-10`) omits

   (`feat_params.py:31-37`). pstrain's file is strictly more complete; I did **not** check whether
   the extra keys change PocketSphinx behaviour versus letting them default.

   was not pursued.

## ERRATUM (2026-08-10)

The audit's claim that tied-CD Baum-Welch does not override the transition
probability floor was incorrect. Upstream explicitly passes `-tpfloor 1e-5`
for tied-CD training in `scripts/50.cd_hmm_tied/baum_welch.pl:88,158`.
Therefore the upstream floor is stage-dependent: the `bw` default `1e-4` is
used for CI and CD-untied, while tied-CD stages use `1e-5`.
