# W8 parameter-count control-file hardening

## 2026-08-16 fold-in: zero-utterance post-condition

- `param_cnt` now records only utterances that reach the counting callback successfully and rejects
  a zero count with a diagnostic that names `-ctlfn` and its path.
- Counts output is opened only after corpus enumeration succeeds and the utterance count is nonzero.
  Empty, whitespace-only, and indented-comment-only controls therefore fail without leaving an
  output file at either the standalone or CFFI boundary.
- Boundary tests retain the established failures for empty files, directories, mode-`000` files,
  `/dev/null`, and a malformed second control line. The output reordering also removes the empty
  file formerly created before the malformed-second-line failure.
- The shared corpus reader is unchanged.

Verification: the focused standalone and CFFI regression suite passed 28 tests. The canonical
`make verified` gate passed: six C tests, 694 Python tests (one skipped and one deselected), the
floating-point contract, configuration checks, Ruff, mypy, and formatting checks were green.
